# tovinodemaker

Настройка сервера под ноду [Remnawave](https://remna.st): установка ноды,
безопасность, сеть, обход блокировок для нейросетей и диагностика — из одного
меню, на Ubuntu/Debian, от root.

## Первая настройка (один раз, у себя в репозитории)

1. Положите в свой репозиторий на GitHub файл `tovinodemaker` и каталог
   `vendor/` целиком.
2. В начале `tovinodemaker` впишите адрес своего репозитория:

   ```python
   REPO_RAW_BASE = "https://raw.githubusercontent.com/<логин>/<репозиторий>/main"
   ```

   Тогда скрипт сам обновляется при запуске и берёт сторонние скрипты из
   вашего `vendor/` с проверкой sha256. Если оставить пусто — самообновления
   не будет, а сторонние скрипты будут скачиваться у авторов; при выходе у
   автора новой версии проверка sha256 её не пропустит, и пункт перестанет
   работать, пока вы не обновите копию.
3. Репозиторий закрытый, поэтому серверам нужен токен на чтение. Создайте
   на GitHub: Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token. Repository access — только этот
   репозиторий, Permissions → Contents: Read-only. Токен вводится при первом
   запуске (см. ниже), скрипт сохраняет его в `/etc/tovinodemaker/github-token`
   (права 600) и дальше берёт оттуда. В файлы репозитория токен не пишите.
4. По желанию — впишите свои SSH-ключи в `DEFAULT_SSH_KEYS`. Тогда блок
   «SSH-ключи» ставит их без вопросов; иначе спрашивает при запуске.

## Запуск на сервере

```bash
read -rsp 'Токен: ' TOVI_GITHUB_TOKEN && export TOVI_GITHUB_TOKEN && curl -fsSL -K <(printf 'header = "Authorization: token %s"\n' "$TOVI_GITHUB_TOKEN") https://raw.githubusercontent.com/Vovunia/ToviNodeMaker/main/tovinodemaker | sudo --preserve-env=TOVI_GITHUB_TOKEN python3
```

Команда спрашивает токен скрыто и не показывает его в `ps` и истории
команд. Если токен отозван или истёк — запустите эту же команду с новым
токеном, он перезапишет сохранённый.

После первого запуска скрипт ставит себя командами `tovi`, `tovinode` и
`tovinodemaker`.

## Что умеет

**Настройка ноды** (галочками; уже настроенное идёт без галочки):

| Блок | Что делает |
|---|---|
| Установка Remnawave Node | Docker, compose, логи; спрашивает `SECRET_KEY` и порт |
| Установка пакетов | fail2ban, ufw, unattended-upgrades, cron |
| SSH-ключи | ставит ваши ключи и закрывает вход по паролю — только если ключи действительно легли в файл |
| Ядро | ставит свежее ядро из репозитория, сверяет работающее с трекером Ubuntu по CVE, в конце предлагает перезагрузку |
| Порядок загрузки (EFI) | хук apt: обновления grub не ставят Ubuntu первым в прошивке (у хостеров первой часто стоит загрузка по сети — rescue и переустановка). Показывается, только если это нужно |
| Часовой пояс + cron | Europe/Moscow, перезагрузка в 03:00 ежедневно или по понедельникам |
| Fail2Ban, UFW | защита SSH, файрвол, закрытие исходящих портов |
| Сеть | BBR, буферы и conntrack по объёму RAM, RPS по ядрам |
| Логи remnanode, обновление ноды | ротация логов, `docker compose pull` |
| Psiphon | чистый выход для Gemini/ChatGPT, до 4 туннелей, сторож со сменой страны |
| Блокировка торрентов | tblocker + резервный фильтр на nftables |
| Ограничение скорости порта | чтобы не упираться в канал хостера |

**Tools:** Remnawave Backup & Restore (distillium) с очисткой старых бэкапов в
Google Drive, управление SSH-ключами (входы, неудачные попытки, пароль
вкл/выкл), ядро и уязвимости, ограничение скорости, SOCKS5-прокси Dante,
проверка обновлений сторонних скриптов, подбор SNI для Reality.

**Тесты:** локаль Google (пустит ли Gemini), тест регионов, скорость до Европы
и России, доступность Telegram.

## Важно

- Блок UFW открывает SSH и 80/443/8443/9999; порт панели (2222) можно
  ограничить адресом панели — спрашивается при настройке.
- Блок cron включает автоматическую перезагрузку в 03:00 МСК.
- Если dpkg застрял на чужом пакете (частая беда образов хостеров — в
  настройке grub остаётся диск виртуальной машины, на которой собирали
  образ), скрипт достраивает пакеты сам и сохраняет порядок загрузки.
